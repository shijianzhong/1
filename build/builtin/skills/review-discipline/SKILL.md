# Review与改稿纪律（A6 content-reviewer）

阶段6 review自检按本纪律跑。初稿写完不能直接交付，走一轮对抗式自检验证内容合理+爆款特质+对标对比。**未过 review 不交付。**

## A6 内闭环改稿（路线1，已定）

A6 拿到 A4 初稿后在**自身 tool-use 循环内** review → 判返工 → 调 `file_write` 改稿 → 再审，收敛或达迭代上限（≤3 轮）终稿交付。图仍纯线性（A1→A2→A3→A4→A5→A6），不加回路边、不碰引擎环检测。审改同由 A6 担任。等 context_mode 落地后再评估升级为"条件边回流 A6→A4"的审改分离。

## 四步 review

### 1. 内容合理性核验
技术主张对不对、有没有硬伤、引用的原文/项目/star 数是否属实（**防 AI 编造**）。
- `gh_search`(action=repo_view) 回查 GitHub 仓库 star/issue/fork 数
- `exa_search` / `web_read` 回查原文和公告
- 核验不过的事实必须改或删

### 2. 爆款特质打分（5维，每维 0-2，总分/10）
| 维度 | 0分 | 1分 | 2分 |
|------|-----|-----|-----|
| 标题打开率 | 无张力 | 有钩子 | 冲突/反差/极短口语命中公式 |
| 开头留存 | 铺垫长 | 3秒可懂 | 反差/故事/数据+痛点共鸣 |
| 金句转发 | 无 | 有1句 | 有1句且可转发型 |
| 真实感(过原创) | 全AI腔 | 有少量人称 | 有真实经历/数据/立场 |
| 互动钩子 | "你怎么看" | 有问题但空泛 | 具体读者答得上的问题 |

<6 分必须返工。

### 3. 对标账号对比
拿这篇和样文库翘楚样文（`sample_article_read`）比，标题/结构/语气/深度差在哪，列出"还差几步能到头部水平"。

### 4. AI腔逐句诊断（治本，两层架构）

> **理念来源**：Roland《我找到了AI写作问题的根源》。AI腔不是"用了哪些常用词"，是**句子与原材料之间的关系出了问题**——读者要做的理解工作没减少。删词换词治标不治本，要审的是"事实—解释—结论三层有没有被压成一句话、原材料撑不撑得起这层归因"。

**两层架构（标准化）**：
- ① 第一层：调 `ai_cavity_audit` 工具做规则预筛——逐句扫，输出透明命中清单（自造说法候选 + `反映出/体现出/表明了` 连接词位置 + 前后句关系待核），零 LLM 成本、可解释。规则只做定位不判断。
- ② 第二层：A6 拿预筛清单 + 下面的两类根源判据逐条定夺改写，LLM 判语义关系。

**AI腔的两类根源（逐句扫，命中即改）：**

#### 根源A：自造说法（给事实换名字）
文中凡是要读者**先理解作者发明的说法、再去理解事实本身**的，且该说法没增加信息的，一律删掉换回事实。
自查法：每个比喻/行话先问"它说的就是哪个普通事实？"。换回事实后信息不丢 → 该比喻没增加信息 → 删。
- "执行成本发生了塌方" → 说的就是成本大幅下降。删比喻，写"成本大幅下降"。
- "活下来的继续加码，死掉的当场埋掉" → 说的就是表现好的追加投入、表现差的砍掉。
判断标准：**删掉自造说法不会损失信息**——原句只是给普通事实换了个名字。

#### 根源B：英译式话语连接造成的语义关系错配（最常被忽视）
英文分析写作用分词补解释（reflecting…），AI 译成中文常换成"反映出""体现出""表明了""揭示了""这意味着""由此可见"。造成**两层错位**：
1. **语法错位**：英文 reflecting 是分词补解释；中文逗号后省略主语时读者沿用前句主语。例：> 多家公司增加交付人员，反映出企业仍需处理数据和流程问题。——读者读成"多家公司反映出…"，主语错位。
2. **证据错位（更要命）**："反映出"把作者的解释接在事实后面，**读起来像前面的事实已经证明了后面的判断**。但企业增加交付人员的原因可能有很多（客户增加、进入交付期、预算增加……），单项事实撑不起"企业仍需处理数据和流程问题"这个归因。

**自查操作流程（对每个连接词执行）：**
1. 把"反映出/体现出/表明了/揭示了/这意味着/由此可见"等**暂时删掉**，前后两句分开读。
2. 问三个问题：
   - 前面是**一项可确认的事实**吗？
   - 后面是**另一个事实**，还是对**原因的解释/推出的结论**？
   - **原材料真的建立了这层关系**吗（因果/相关）？还是作者自己加的归因？
3. 按原材料支持程度重写连接：

| 原材料支持到什么程度 | 该怎么写 |
|---------------------|---------|
| 确认了原因 | "原因是" |
| 只是同一时期出现 | "与……同时出现" |
| 只能支持一种可能 | "可能与……有关" |
| 没建立关系 | 连接词直接删，解释一并删 |

**核心原则**：作者承担了什么判断、原材料支持到哪里，读者都得能看见。一项事实+一种解释+一个结论被"反映出"压在一句话里时，读者看不到作者省略了哪一步——拆开。

**命中 ≥3 处 → 真实感维封顶 1 分并标"需返工逐句改"。**

## 明确结论

✅ 可发 / ⚠️ 需返工（列具体改点）/ ❌ 推倒重写（理由）。

判返工则进入内闭环：调 `file_write` 改稿 → 再跑 `ai_cavity_audit` + 5维打分，收敛或达迭代上限（≤3 轮）终稿交付。

收敛后调 `review_archive_save` 把最终 review（5维打分+对标对比+改点+AI腔命中+发布前微调）落进 review 档案库，供后续迭代风格画像。

## Discipline

review 必须四步全走（事实核验+5维打分+对标对比+AI腔逐句诊断），不能只打分不核验事实。事实硬伤（编造 star/数据/原文）必须改或删，不放过。AI腔走两层：先 `ai_cavity_audit` 规则预筛拿命中清单，再逐条定夺改写——规则只定位不判断，定性靠语义。<6分或≥3处AI腔命中必须返工，判返工则内闭环改稿再审直到收敛（≤3轮）。终稿落 `review_archive_save` 档案库。未过 review 不交付。
