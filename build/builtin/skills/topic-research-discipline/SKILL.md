# 选题调研纪律（A1 content-researcher）

阶段1选题调研按本纪律跑。所有平台抓取走内置工具（exa_search / gh_search / reddit_search / web_search / web_read），不自己 curl 瞎猜。平台按"搜索价值+讨论热度+趋势验证"三类并行跑，最后汇总成选题价值评估表。

## 调研工具映射

| 平台 | 工具 | 用途 |
|------|------|------|
| 语义趋势 | `exa_search` | 近3-6个月新内容，抓选题角度和爆款标题 |
| GitHub | `gh_search`(action=search_repos) | 锁真火项目（star>5K 或近30天 trending），避免写过气 |
| GitHub 核验 | `gh_search`(action=repo_view) | 查某仓库 star/issue 元数据，防 AI 编造 |
| Reddit | `reddit_search` | 海外开发者讨论热度，海外火国内没写=选题红利 |
| 全网 | `web_search` | 微信指数/百度/搜狗同题文章数（红海度判断） |
| 读全文 | `web_read` | 读重点文章/帖子/公告全文 |

## 三类并行调研

1. **趋势与选题**：`exa_search`（query="<方向> 2026 趋势 爆款 实战"，numResults=8，带 startPublishedDate 提时效）
2. **GitHub 锁真火**：`gh_search`(action=search_repos, query="<方向关键词>", limit=20) + 限定 `--created=">2026-01-01"` 找新项目。**硬规则**：写工具盘点类，项目必须 star>5K 或近30天 trending，否则不写。
3. **Reddit 验证全球热度**：`reddit_search`(query, subreddit=LocalLLaMA/programming 等, sort=hot)。看 upvote 高的帖，海外火的国内公众号还没写=选题红利。

## 选题评审决策（调研完必做，不能只列数据）

调研完先出"选题价值评估表"，再对每个候选过评审，给明确结论。**不靠临场经验，按下面固化的判断标准走。**

### 选题价值评估表

| 选题 | 热度信号(GitHub star/讨论量) | 搜索价值(微信指数/百度) | 对标空白(红海/机会/空白) | 推荐度 |
|------|-----------------------------|------------------------|--------------------------|--------|

### 三维过筛（每个候选选题过三关）

1. **热度背书关**：选题背后的项目/概念有没有真实热度？
   - GitHub star>5K 或近30天 trending → ✅ 过
   - star=0 / 无人关注 → ❌ 本身没背书，**必须搭一个有热度的大概念**补背书（如原仓库 star=0，但 Context Engineering 大方向 7月顶热 → 可做，背书靠大概念而非原仓库）
   - 搭不上大概念 → 否决
2. **红海度关**：国内公众号同题覆盖多少？
   - 搜狗同题 <3 篇 → 蓝海，可正面写
   - 3-8 篇 → 有热度，需差异化切口
   - >8 篇且角度趋同 → 红海，除非有强差异切口，否则否决
3. **实现空白区关**：概念红海里有没有"实现/案例/落地"的空白？
   - 国内号都在讲"X是什么"（概念层），没人讲"X具体怎么实现"（实现层）→ 这是红海里的空白区，红利最高
   - 没有空白区 → 慎入

### 跑偏校验（防选题跑偏的硬规则）

判断切口是不是"介绍某个没热度的具体仓库/文章"：
- ❌ 跑偏：切口是"介绍 star=0 的原仓库/原文章"——读者会问"这谁？没人用"，无热度背书
- ✅ 正确：转成"借这篇文章/仓库的实现，讲透一个国内号还没写的有热度具体问题"
- 红海概念选题必须做这个转换，从"介绍"转"借它讲透"

### 切口选择（给2-3个候选，标红利度，推荐差异化最高的）

对每个通过的选题，给 2-3 个具体切口候选，按红利度排序：
- 🟢 高：概念红海里的实现空白区
- 🟡 中：对比式/争议式深度
- 🔴 低：纯介绍/纯盘点

### 判断结论（必给，不能只列数据）

每个候选选题明确说一句：
- ✅ 可行，切口用 X（红利度+理由）
- ⚠️ 需调角度：原角度跑偏（理由），改成 Y
- ❌ 否决：理由

### 套标题公式预演

对推荐切口，套 `writing-style` 技能的标题公式各拟 1 个，验证切口能否落地成好标题。标题立不住的切口，说明选题没想清，回去调。

## 收尾

挑 3 个高价值（过三维筛+不跑偏+切口红利高），调 `topic_add` 工具追加进选题库，附带判断结论和推荐切口。失败重试：429 限流时等几秒重试或换平台先跑。

## Discipline

调研必须出"价值评估表+三维过筛+判断结论"三件套，不能只列数据。每个候选选题明确说"可行/需调角度/否决"+理由。引入的项目必须有真实热度背书（star>5K 或搭大概念），写过气项目=零热度。跑偏的选题必须从"介绍"转"借它讲透"。最终用 `topic_add` 落库，附判断结论。
